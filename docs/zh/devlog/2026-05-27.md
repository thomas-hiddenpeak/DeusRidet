# DEVLOG 2026-05-27

## Phase 3c — 生产环境说话人分离链路的首次语义阅读

数据来源：`runs/20260526T051055_replay_s600/` — `tests/test.mp3` 前 600s
以 4× 速率回放，reclusterer 全开（默认参数：W=180s, S=30s, K∈[2,6],
link=0.55, ema=0.20, min_segs=12, max_segs=300，dual-encoder 384D）。

按系统级规则"语义判断禁止脚本打分"（`workflow.instructions.md`
§Semantic Evaluation，commit 40ab28d），agent 直接对照
`tests/fixtures/test_ground_truth.json` 阅读 transcript.md。以下为
*现象 → 证据 → 怀疑成因 → 候选干预*，不报 macro-F1。

### 现象一 — 首次 reclusterer 触发即把 4 个 GT 说话人坍缩成 2 个全局

**证据。** 600s 结束时的 forward-map 是 `{0,1,2,5} → 1000`、
`{3,4} → 1001`。GT 有四个说话人（朱杰 / 徐子景 / 唐云峰 / 石一），系统
最终只剩两个全局。所有合并都发生在 `t=03:24.500`（180s 预热后的第一个
窗口结束点）：单次窗口推断里 raw `0`、`1`、`2` 全部被映射到 global
`1000`，raw `3` 被映射到 `1001`。后续 `04:10.700`、`05:12.400` 的 pass
只是把这两个桶继续累加。

**怀疑成因。** 窗口内 K 选择看起来是健康的——eval driver 全语料日志里
"Optimal K=4 / K=5" 在多个窗口出现。所以坍缩的责任不在 spectral
clustering，而在 **跨窗口 Hungarian linker**。第一个窗口（00:00–03:00）
里 raw=0 主要承担朱杰的长独白（00:22–00:39，约 10 秒干净）；raw=1
散落在朱杰 / 徐子景 / 唐云峰 的短轮中；raw=3 在 01:42 才开始作为唐云峰
出现。Hungarian linker 面对一个仍被朱杰证据主导的 384D centroid，把
raw=1 + raw=2 + raw=0 都判为"同一 global"（链接阈值 0.55 在 EMA
centroid 尚未分离时太宽松），然后给 raw=3 单独分配一个 global。这印证
了 `2026-05-26.md` 的 Phase 14 工作假设："full_60m macro_f1 的瓶颈
在跨窗口 Hungarian 链接稳定性。"生产数据现在确认了这个判断。

**候选干预。**
- 把 linker 阈值 0.55 → 0.65 **仅在 bootstrap 阶段**生效（例如前
  N≤2 个窗口），或者让阈值随 EMA centroid 已吸收的 segment 数量动态
  收紧。
- 要求 linker 双向同意（候选必须同时是双方的最佳匹配，而不是单边
  "高于 0.55"）。
- bootstrap 延迟：`min_segs` 12 → ~24，或者强制至少 2 个窗口之后才允许
  发出第一个 relabel 事件。让 raw ID 先累积更厚的证据。

### 现象二 — 约 05:18 之后，4 个全局成型，系统自我修正

**证据。** `06:16.800` 起出现 raw `7`，到 `07:05` 都很干净——所有
overlap 都是 `GT=徐子景 pred=7`。`07:20.100` 起出现 raw `6`，在
`08:43` 之前主导石一区段（08:24/08:26 夹了两个唐云峰短句，因为石一/
唐云峰在快速对话）。关键是：raw=6 和 raw=7 **不在** forward-map 中，
reclusterer 从未尝试把它们合并。也就是说，一旦 4 个全局已经"挑出来"
且彼此分离够远，linker 是会保住身份的。病灶仅限于 bootstrap。

**含义。** 这是好消息——稳态行为是正确的。bug 局限于前 3–5 分钟，
EMA centroid 尚未成熟的阶段。一套"bootstrap 感知"的策略（延迟首次
relabel、年轻 centroid 期用更紧阈值）应当是高杠杆修复点。

### 现象三 — 一段长独白中途切换 global

**证据。** 唐云峰 03:27–03:58 的独白前半（03:27–03:43）是
`pred=1000`（raw=1），后半（03:47–03:55）是 `pred=1001`（raw=3）。
同一说话人、同一连续讲话，被打成两个不同全局。在线 linker 在同一段
speech event 里发出了 raw=1 和 raw=3 两个不同 raw ID；reclusterer
随后把 raw=1 映射到朱杰所在的 global（1000）、raw=3 映射到它自己的
global（1001）——把唐云峰的一段独白切成读起来是两个人。

**怀疑成因。** 上游 raw-cluster 碎片化：在线说话人识别 + 段落 linker
栈在一次连续讲话内发出多个 raw ID。reclusterer 本来就是来修这个的，
但它修的方向是错的，原因就是现象一。

**候选干预。** 修好现象一基本就修好这条——如果 raw=1 当初被关联到
raw=3（都是唐云峰）而不是 raw=0（朱杰），这段独白就连贯了。所以
linker 策略修复是关键路径。

### 现象四 — Margin-abstain 表现良好

**证据。** 约 25 个 `pred=-1`，几乎全部落在：(a) ≤0.5s 起始片段；
(b) 两人重叠区；(c) VAD 抓到但 speaker-ID 正确拒答的 "嗯/啊"
backchannel。没有一个 `pred=-1` 落在自信的长句上。保守 abstain 通路
工作正常，不是错误源。

**结论。** 此处无需修改。

### 现象五 — VAD 整段丢掉约 12 个短句

**证据。** "no runtime segment overlaps this utterance" 在前 600s 内
出现 12 次，全在 ≤2s 的话语（如 03:03 朱杰"啊？"、08:21 唐云峰"嗯。"、
09:26 徐子景"对."）。都是 backchannel 与单音节插入。

**怀疑成因。** SileroVAD / FSMN-VAD 的 min-speech-ms 门限太长，或者
25ms hangover 不足以保住孤立的"是/否"音节。这是 `sensus`（感知）问题，
不是 `orator` 问题。

**结论。** 出 Phase 3 范围。等后续对话理解栈开始关心 backchannel 时
再做 VAD 调参。

## 对 3b/3c 路线图的结论

主要失效模式是 **bootstrap 阶段的 Hungarian linker 过度合并**，
不是窗口内 spectral clustering 的问题，也不是 forward-map 机制的
问题。这个判断是直接读 transcript 得到的——我在 Phase 8–14 试过的所有
数值打分杠杆，要么 full_60m 回退、要么 s1800 移动 ≤1pp，因为它们都作用
在错误的子系统上。
