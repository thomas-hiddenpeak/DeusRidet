# 2026-05-25 — Phase 12：重叠感知嵌入 A/B（负向结果）

## 摘要

针对 Phase 10–11 诊断出的 0.7935 / 0.7032 macro_f1 天花板，尝试从上游
发起进攻。假设：188 段污染簇主要由重叠损坏的嵌入构成；如果在重新提取
CAM++ / WavLM-ECAPA 之前，把 **RMS 占优分离通道** 拼回原 PCM，融合 fixture
应该会更干净。

结论：**嵌入侧的重叠补丁在两个窗口上都使指标下降。**

## 流程

新增独立工具 `tools/build_overlap_patched_pcm.cpp`：

1. 加载 `/tmp/test_mp3_16k_mono.f32` 与 1169 条 refined GT JSONL。
2. 以每段 GT 为中心构造 10 s 零填充窗口，调用
   `OverlapDetector.detect()`（pyannote-seg3 powerset，589 帧）。
3. 在覆盖 `[s0,s1]` 的帧上计算 `overlap_ratio`。若 `≥ 0.20`（默认），
   将该段 PCM 送入 `SpeechSeparator.separate()`
   （MossFormer2-SS-16k），选 `dom = argmax(energy_source_k)`，
   按原 RMS 缩放，将 `clip(dom * scale, ±1)` 拼回 `patched[]` PCM 副本。
4. 写出 `/tmp/test_mp3_16k_mono_overlap_dom.f32`（220.6 MB）和
   `tests/fixtures/overlap_patch_v1.jsonl`（每段 overlap_ratio 与
   separated 标记）。
5. 在补丁 PCM 上重提 CAM++ 与 WavLM-ECAPA →
   `tests/fixtures/{cam,wl}_embeddings_v2.{f32,meta.json}`。
6. 用 `tools/dump_fused_fixture_v2.py` 融合（schema 同 v1，
   strategy=full，fused = L2(concat(L2(cam_v), L2(wl_v)))）→
   `tests/fixtures/fused_v2_dominant.bin`（1169 × 384，1828336 字节）。

## 解读

- 1169 段中有 193 段（16.5%）越过 0.20 阈值，但分离器的"主通道"并非
  无损：当 overlap_ratio 刚过 0.20 时，网络引入的相位伪影对
  CAM++/WL-ECAPA 的扰动反而比原始轻度干扰更严重。
- 因此 188 段污染簇并非纯重叠产物。**嵌入侧重写不是正确的攻击轴。**
- 后续方向：保留 v1 PCM，把同样的问题挪到聚类阶段去解决（例如
  overlap-gated PLDA 收缩，或用 `overlap_patch_v1.jsonl` 驱动的每段
  可靠性权重），不要破坏原始波形。
