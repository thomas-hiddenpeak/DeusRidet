### Hybrid P2 — Transcript holdback + 周期重聚类

朴素方案会改写 LLM 已经 tokenise 过的条目的 `speaker_id`，造成 KV cache
失效。Plan A (holdback) 绕开：

- **`TranscriptHoldback`** (`src/sensus/auditus/transcript_holdback.{h,cpp}`)
  是 ASR → `ConscientiaStream::inject_input` 之间的 FIFO。一个 250ms
  drainer 线程在条目 stream-time 龄 ≥ `DEUSRIDET_TRANSCRIPT_HOLDBACK_SEC`
  (默认 75s) 才释放。释放前 `apply_diarization()` 按每条 pending 取
  argmax overlap label，再通过对 `committed_` 历史 (cap 1024) 的
  贪心分配 + 弱 (0.25×) pending overlap 先验，解析成
  **跨次稳定的全局 id**。`id_to_name_` 维持跨次名称表稳定。
- **`DiarizenPeriodicWorker`** (`src/orator/diarizen_periodic_worker.{h,cpp}`)
  后台线程，每 `DEUSRIDET_DIARIZEN_PERIOD_SEC` (默认 60s)
  dump 当前捕获 WAV、调 `DiarizenFacade::diarize` 处理快照、
  按 `audio_t1` 原点把段交给 `holdback.apply_diarization()`。
  `trigger_async()` 经 WS `diarizen_trigger` 暴露按需触发
  (HTTP 可移植，供未来 REST handler)。

**Live 证据** (`tests/test.mp3`, speed=8x,
`DEUSRIDET_DIARIZEN_ENABLE=1 PERIOD_SEC=60 HOLDBACK_SEC=75`)：
1658 段 / 753.8s wall / 93.6% accuracy。各 speaker 分布与 P1 一致。
本次未加载 LLM，故 holdback 为预期 no-op (走 P1 fallback)；P2 接线
在 LLM 加载下的端到端验证记入下方"待清门"。

## 27B prefill 已解决 —— 全 GPTQ 投影支持（FA q/k/v/o + DN qkv/z/out）

### 根因

Qwen3.6-27B GPTQ-Int4 checkpoint **完全量化** —— 不仅 MLP
gate/up/down，所有 `self_attn` 投影（`q_proj`/`k_proj`/`v_proj`/
`o_proj`）以及 `linear_attn` 投影（`in_proj_qkv`/`in_proj_z`/
`out_proj`）也是 GPTQ。原 Qwen3.5-9B 参考只量化了 MLP，FA 与 DN
投影仍是 FP16。

加载器 tensor 名识别表
(`model_weights_loader.cpp::is_relevant_tensor`) 没有
attn/DN `*.qweight` / `*.scales` 条目，这些权重被静默丢弃；
`merge_projection_weights` 随后给 repack 目标 `cudaMalloc` 并从
`nullptr` `cudaMemcpy`，得到一块设备垃圾内存。首次 prefill 用这块
垃圾跑 `fp16_gemm`，下一次 `cudaStreamSynchronize` 报
`code 700 — illegal memory access`，env-gated bisect 定位到
`DN L=0 step=z_gemm`。

### 本次提交修复

1. `model.h` —— `FullAttentionWeights` 新增 `GptqWeight
   gq_q,gq_k,gq_v,gq_o`；`DeltaNetWeights` 新增
   `gq_qkv,gq_z,gq_out`。全量化 checkpoint 下 `fp16_*.weight` 可为
   `nullptr`，"投影是 GPTQ" 等价于 `gq_*.qweight != nullptr`。
2. `model_weights_loader.cpp` —— `is_relevant_tensor` 识别 16 个新
   tensor 名（4 FA 投影 × {qweight,scales} + 3 DN 投影 ×
   {qweight,scales}）；`dispatch_tensor` 经
   `assign_gptq_qweight` / `assign_gptq_scales` 路由到新字段。
3. `model_runtime.cpp::merge_projection_weights` —— 每个 repack/merge
   增加 `if (fp16_*.weight != nullptr)` 守护；FA k+v 合并要求两半都
   是 FP16；DN qkv 合并在 `fp16_qkv` 为 null 时跳过。
4. `paged_attention.cu::full_attention_forward_paged_prefill` —— 按投影
   分支：GPTQ 走 `gptq_gemm`，否则走 `linear_forward`，覆盖 q/k/v/o。
5. `forward_prefill.cu::deltanet_prefill` —— 新增
   `scatter_dn_qkv_kernel`：从紧凑的 GPTQ qkv 输出 + 仍为 FP16 的
   a/b 输出拼出步长 `dn_qkv[M, LIN_QKV_AB_DIM]`（A/B 投影极小
   `5120→48`，checkpoint 中没有 GPTQ 形式）。qkv/z/out 各自独立按
   `gptq_gemm` 或 `linear_forward` 分支。
6. `forward.cu` —— decode 路径（M=1）：`full_attention_forward` 与
   `deltanet_forward` 按投影分支 `gptq_gemv` vs `fp16_gemv`。M=1
   不需 scatter，`gptq_gemv` 直接写入步长偏移。
7. `stream.cpp` —— 保留 env-gated 逐步
   `cudaStreamSynchronize` bisect（`DEUSRIDET_DBG_PREFILL_BISECT=1`、
   `DEUSRIDET_DBG_DN_BISECT=1`），未设环境变量时零开销，便于下次
   量化 shape mismatch 排障。
8. `configs/machina.conf` —— `llm_model_dir` 按用户要求指向 27B
   GPTQ-Int4 checkpoint。

### 任务 2 —— cyankiwi Qwen3.6-27B-AWQ-INT4 上的 AWQ A2 探测

**结论：A2（加载时 AWQ → 对称 GPTQ 重量化）不可行；需要
A1（真 AWQ kernel）或接受 dequant→requant 的精度损失。**

cyankiwi/Qwen3.6-27B-AWQ-INT4 的 tensor 清点：
- 格式：compressed-tensors **pack-quantized**，group_size **32**，
  非对称，`zp_dtype=torch.int8`（在文件中以 int32 打包存储）。
- 64 层（与 GPTQ checkpoint 一致），self_attn 在层
  {0,3,7,11,15,19,23,27,31,35,39,43,47,51,55,59,63}，linear_attn
  在剩余 48 层。
- 存储轴是 `[N, K/8]`（与 GPTQ 的 `[K/8, N]` 相反），shape 记录
  在 `*.weight_shape` 中。`*.weight_packed` 为 uint32 按 K 打包；
  `*.weight_scale` 为 `[N, K/32]` fp16；`*.weight_zero_point`
  为 `[N/4, K/32]` int32（4 个 int8 zp 打包）。

zero-point 分布（采样 q_proj L3、o_proj L3、in_proj_qkv L0、
out_proj L0、mlp.gate_proj L0、mlp.down_proj L0）：
- 六个 tensor 全部：`pct(zp==8) = 0.000`，`pct(zp==0) = 0.000`。
- min/max 跨满 int32 范围（zp 是 4 个 int8 packed 进一个 int32 的）；
  解包后 int8 zp 同样跨满范围。
- "AWQ 大致 zp==8 (对称)" 的假设对此 checkpoint **不成立**。
  trivial 的 A2 cast 不会保留数值质量。

决策：**A2 不能作为免费转换路径**。要支持此 checkpoint，三选一：
1. **A1**：实现专用 AWQ 非对称 matmul kernel（最接近的参考是
   Marlin AWQ 变体或 `auto-awq` GEMM）。工作量最大。
2. **A2'**：加载时 dequant → 对称 requant，并测量精度损失
  （需在同一 prompt 集合上对 GPTQ checkpoint 做 A/B sandbox）。
3. **暂搁**：把 GPTQ checkpoint 作为生产 27B 路径。
   Qwen3.6-27B-GPTQ-Int4 已跑通，prefill 69 tok/s，decode 干净。

本工作单元未提交代码。探测制品和上述分析仅记录在此。
