### 诊断 A —— 在线 holdback 为何零修正

首次在线回放测试暴露:TranscriptHoldback 层把每个条目都按其**临时**在线
说话人 id 原样排出 —— 零修正。沿调用图追踪到根因:

- 唯一的说话人 id 改写路径是 holdback 的 `apply_diarization()`。
- 它只被 `DiarizenPeriodicWorker::run_one_pass_()` 调用。
- 该 worker 仅在 `was_triggered || periodic_enabled_` 时跑一次 pass。
- `periodic_enabled_` 默认关闭(需 `DEUSRIDET_DIARIZEN_PERIODIC=1`);
  awaken 日志打印 `periodic=OFF (trigger/finalize only)`。
- `tools/replay_to_transcript.py` 只发 `asr_enable:on`,从不发
  `diarizen_trigger` / `diarizen_finalize`。

因此在普通回放路径里从未跑过 DiariZen pass,`apply_diarization` 从未被调用,
holdback 无可施加。这不是逻辑 bug —— 修正的*触发器*在测试所走的路径里
根本不存在。

### 构建修复 —— vires 链接欠债

`vires::Arbiter` 计算基底 API 现被两个静态库内部引用 —— `machina`
(model_runtime、forward_prefill、forward_decode 注册优先级流)与 `sensus`
(speech_separator 注册分离消费者)。两者仅通过最终 `deusridet` 目标传递链接
vires,因此其它每个消费者(`test_forward`、`test_sample`、
`auditus_separatio_examen` / `_asr` / `_spkid`、`test_mossformer2`、
`bench_mossformer2`、`test_overlap_*`)在链接期都因
`vires::Arbiter::{instance,register_consumer,unregister_consumer,stream,
note_submit}` 未定义引用而失败。

修复:把 vires 声明为 `machina` 与 `sensus` 的 PUBLIC 依赖,使该需求自动
传播到每个消费者。vires 仅依赖 communis + cudart,故不引入依赖环。完整
`make -j` 现以零未定义引用构建全部 43 个目标;纯默认 `awaken` 仍提供
HTTP 200 + WS 101。
