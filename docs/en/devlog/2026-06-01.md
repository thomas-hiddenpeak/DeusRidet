# DEVLOG 2026-06-01

## Vires — broaden Foreground heartbeats to machina prefill/decode + ASR

Commit this session:

- `738fc66` feat(vires): broaden Foreground heartbeats to machina + ASR

`accuracy(tests/test.mp3, diarization): 93.5% → 93.6%   (Δ = +0.1 pp)`

### What shipped

Until now only `orator_spk_encoder` emitted Vires `note_submit`
heartbeats, so the Foreground-yield arbitration — and the WebUI
vires-panel — only reflected speaker-encoder load. Every other
Foreground GPU consumer registered with the Arbiter but never reported
activity, leaving its `submitted` counter pinned at zero and its load
invisible to `background_should_yield()`.

This change adds the same one-line, bit-identical heartbeat to every
Foreground consumer that owns a compute stream:

- machina prefill (`forward_prefill`) → `state.vires_compute_id`
- machina decode (`forward_one_token` / `forward_one_token_sampled`) →
  `state.vires_compute_id`
- auditus ASR encoder (`ASREngine::transcribe`) → `vires_id_`

Each is a single `vires::Arbiter::instance().note_submit(id)` issued
right after the existing `cudaStreamSynchronize`. It changes no kernel,
no math, and no execution order — it only bumps the per-consumer
`submitted` counter and refreshes the `last_foreground_submit_us_`
timestamp that the Background DiariZen path reads to decide whether to
yield. `note_submit` takes a single short-held mutex with no nested
locks or callbacks, so there is no deadlock or reordering risk.

The net effect: `background_should_yield()` now honours true Foreground
load across all active consumers (not just the speaker encoder), and the
WebUI vires-panel shows real `submitted` counts for prefill, decode, and
ASR instead of a flat zero.

### Live verification (the Constitutional gate)

Full live run via `tools/diarizen_live_score.py` against `tests/test.mp3`
(3615.1 s) at speed 8×, finalised through the native pipeline:

- 1653 segments, `audio_sec=3615.12`, `wall_sec=359.91`
- 527 / 531 GT utterances decided, coverage 0.992
- macro = 0.916, **micro = 0.936**
- per-speaker (decided-only): 唐云峰 0.939 · 徐子景 0.920 · 朱杰 0.835 ·
  石一 0.971
- **`accuracy(tests/test.mp3, diarization): 93.5% → 93.6%   (Δ = +0.1 pp)`**

The heartbeats are bit-identical to the GPU math by construction, so
diarization accuracy is unchanged within run-to-run noise. The live
`spk_encoder` heartbeat was confirmed climbing in the same run
(`submitted` 63 → 240, `background_yielding` flips `True` at
`foreground_idle_us=4073`). The machina and ASR heartbeats are
correct-by-construction — identical one-line pattern, clean build — and
only become observable under a non-saturating run (at 8× the pipeline
saturates: 16 833 `audio_drop` events starve the ASR worker, and the
diarizen gate does not trigger LLM decode).
