### What was actually built vs. RFC plan

`docs/{en,zh}/architecture/12-diarizen.md` defined a six-phase native CUDA
port (P1a..P3c) — port WavLM-Large 25-hidden tap, port the Conformer head,
write a CUDA segmentation orchestrator, port ResNet34 embedder, port VBx
clustering, then wire the whole thing into `awaken`. We did **not** take
that path. Instead we shipped an IPC fast-path that calls the already-
working Python DiariZen-v2 stack out-of-process:

| RFC phase | Status | Note |
|-----------|--------|------|
| P0 (this RFC + converter) | ✅ done `d334434` | unchanged |
| P1a/b/c (native segmentation) | ⏸ deferred | replaced by P-IPC |
| P2a/b (native embedding + VBx) | ⏸ deferred | replaced by P-IPC |
| P3a (facade) | ✅ via IPC `e96255b` | `DiarizenFacade` shells out |
| P3b (awaken integration) | ✅ via IPC `b0e3a8f` + `0cc9d0d` | WS `diarizen_finalize` + periodic |
| P3c (default flip) | ⏸ deferred | still env-gated `DEUSRIDET_DIARIZEN_ENABLE=1` |

### Hybrid P1 — Live-system wiring

`AudioPipeline` grew a session-capture tap (atomic-gated, mutex-guarded PCM
buffer + RIFF WAV dump). `awaken` exposes a WS text command
`diarizen_finalize` that dumps `/tmp/diarizen_session.wav`, runs
`DiarizenFacade` on a detached thread, and broadcasts
`speaker_diarize_final` with the full segment list. Verified against
`tests/test.mp3` (3615s at speed=8x):

- 1658 segments returned in 753.7s wall (RTF ≈ 0.21 on Orin)
- 527 / 531 GT utterances decided, coverage 0.992
- bit-equal segment list vs the offline DiariZen-v2 driver on the same
  captured WAV (1658 segments, per-label durations within 0.02s)
- `tools/diarizen_live_score.py` is the Constitutional accuracy gate

### Hybrid P2 — Transcript holdback + periodic recluster

The naive periodic-recluster design would have rewritten `speaker_id` on
items the LLM had already tokenised, invalidating KV cache. Plan A
(holdback) avoids that:

- **`TranscriptHoldback`** (`src/sensus/auditus/transcript_holdback.{h,cpp}`)
  is a FIFO between ASR and `ConscientiaStream::inject_input`. A 250ms
  drainer thread releases items only after they have aged
  `DEUSRIDET_TRANSCRIPT_HOLDBACK_SEC` stream-time seconds (default 75s).
  Before release, `apply_diarization()` picks the per-pending-item argmax
  overlap label, then resolves it to a **cross-run-stable global id**
  via greedy assignment against a `committed_` history (cap 1024) with a
  weak (0.25×) pending-overlap prior. `id_to_name_` keeps the friendly
  name table stable across passes.
- **`DiarizenPeriodicWorker`** (`src/orator/diarizen_periodic_worker.{h,cpp}`)
  is a background thread that every `DEUSRIDET_DIARIZEN_PERIOD_SEC`
  (default 60s) dumps the running capture WAV, calls
  `DiarizenFacade::diarize` on the snapshot, and hands the resulting
  segments to `holdback.apply_diarization()` aligned to the correct
  `audio_t1` origin. `trigger_async()` exposes on-demand reclustering via
  WS `diarizen_trigger` (HTTP-portable API for a future REST handler).

**Live evidence** (`tests/test.mp3`, speed=8x,
`DEUSRIDET_DIARIZEN_ENABLE=1 PERIOD_SEC=60 HOLDBACK_SEC=75`):
1658 segments / 753.8s wall / 93.6% accuracy. Identical per-speaker
breakdown to P1. The LLM was not loaded in this run, so holdback was an
intentional no-op (P1 fallback path); the P2 wiring still has to be
exercised end-to-end with the LLM loaded — recorded as the next gate
below.

### Hybrid P2 — WebUI surface

`src/nexus/webui/js/components/diarizen-panel.js` is a new panel:
"Trigger Now" + "Finalize" buttons send WS `diarizen_trigger` /
`diarizen_finalize`; the panel renders the latest
`speaker_diarize_progress` / `_partial` / `_final` messages with
pass-number, status, segment-count, origin-sec, per-label duration
table, and a rolling 20-line history. The asset is served by the
generic static handler in `ws_server_http.cpp` (no registry edit
needed) and responds `200` at `/js/components/diarizen-panel.js`.
