### What was actually built vs. RFC plan

`docs/{en,zh}/architecture/12-diarizen.md` defined a six-phase native CUDA
port (P1a..P3c) — port WavLM-Large 25-hidden tap, port the Conformer head,
write a CUDA segmentation orchestrator, port ResNet34 embedder, port VBx
clustering, then wire the whole thing into `awaken`. We did **not** take
that path. Instead we shipped an IPC fast-path that calls the already-
working Python DiariZen-v2 stack out-of-process:

| RFC phase | Status | Note |
|-----------|--------|------|
| P0 (this RFC + converter) | ✅ done `d334434` | unchanged |
| P1a/b/c (native segmentation) | ⏸ deferred | replaced by P-IPC |
| P2a/b (native embedding + VBx) | ⏸ deferred | replaced by P-IPC |
| P3a (facade) | ✅ via IPC `e96255b` | `DiarizenFacade` shells out |
| P3b (awaken integration) | ✅ via IPC `b0e3a8f` + `0cc9d0d` | WS `diarizen_finalize` + periodic |
| P3c (default flip) | ⏸ deferred | still env-gated `DEUSRIDET_DIARIZEN_ENABLE=1` |

### Hybrid P1 — Live-system wiring

`AudioPipeline` grew a session-capture tap (atomic-gated, mutex-guarded PCM
buffer + RIFF WAV dump). `awaken` exposes a WS text command
`diarizen_finalize` that dumps `/tmp/diarizen_session.wav`, runs
`DiarizenFacade` on a detached thread, and broadcasts
`speaker_diarize_final` with the full segment list. Verified against
`tests/test.mp3` (3615s at speed=8x):

- 1658 segments returned in 753.7s wall (RTF ≈ 0.21 on Orin)
- 527 / 531 GT utterances decided, coverage 0.992
- bit-equal segment list vs the offline DiariZen-v2 driver on the same
  captured WAV (1658 segments, per-label durations within 0.02s)
- `tools/diarizen_live_score.py` is the Constitutional accuracy gate

### Hybrid P2 — Transcript holdback + periodic recluster

The naive periodic-recluster design would have rewritten `speaker_id` on
items the LLM had already tokenised, invalidating KV cache. Plan A
(holdback) avoids that:

- **`TranscriptHoldback`** (`src/sensus/auditus/transcript_holdback.{h,cpp}`)
  is a FIFO between ASR and `ConscientiaStream::inject_input`. A 250ms
  drainer thread releases items only after they have aged
  `DEUSRIDET_TRANSCRIPT_HOLDBACK_SEC` stream-time seconds (default 75s).
  Before release, `apply_diarization()` picks the per-pending-item argmax
  overlap label, then resolves it to a **cross-run-stable global id**
  via greedy assignment against a `committed_` history (cap 1024) with a
  weak (0.25×) pending-overlap prior. `id_to_name_` keeps the friendly
  name table stable across passes.
- **`DiarizenPeriodicWorker`** (`src/orator/diarizen_periodic_worker.{h,cpp}`)
  is a background thread that every `DEUSRIDET_DIARIZEN_PERIOD_SEC`
  (default 60s) dumps the running capture WAV, calls
  `DiarizenFacade::diarize` on the snapshot, and hands the resulting
  segments to `holdback.apply_diarization()` aligned to the correct
  `audio_t1` origin. `trigger_async()` exposes on-demand reclustering via
  WS `diarizen_trigger` (HTTP-portable API for a future REST handler).

**Live evidence** (`tests/test.mp3`, speed=8x,
`DEUSRIDET_DIARIZEN_ENABLE=1 PERIOD_SEC=60 HOLDBACK_SEC=75`):
1658 segments / 753.8s wall / 93.6% accuracy. Identical per-speaker
breakdown to P1. The LLM was not loaded in this run, so holdback was an
intentional no-op (P1 fallback path); the P2 wiring still has to be
exercised end-to-end with the LLM loaded — recorded as the next gate
below.

## 27B prefill RESOLVED — full GPTQ projection support (FA q/k/v/o + DN qkv/z/out)

### Root cause

The Qwen3.6-27B GPTQ-Int4 checkpoint is **fully quantized** — not only
MLP gate/up/down, but also every projection in `self_attn`
(`q_proj`/`k_proj`/`v_proj`/`o_proj`) and `linear_attn`
(`in_proj_qkv`/`in_proj_z`/`out_proj`). The previous Qwen3.5-9B
reference only quantized MLP; FA and DN projections were FP16.

The loader's tensor-name recognition table
(`model_weights_loader.cpp::is_relevant_tensor`) had no entries for
the attn/DN `*.qweight` / `*.scales` keys, so those weights were
silently dropped. `merge_projection_weights` then `cudaMalloc`'d the
repack target and `cudaMemcpy`'d FROM `nullptr`, producing garbage
device buffers. The first prefill launched `fp16_gemm` against those
garbage buffers and the next `cudaStreamSynchronize` reported
`code 700 — illegal memory access` after `DN L=0 step=z_gemm`
(confirmed by env-gated bisect).

### Fix (this commit)

1. `model.h` — added `GptqWeight gq_q,gq_k,gq_v,gq_o` to
   `FullAttentionWeights` and `gq_qkv,gq_z,gq_out` to
   `DeltaNetWeights`. `fp16_*.weight` may be `nullptr` in fully
   quantized checkpoints; "projection is GPTQ when `gq_*.qweight !=
   nullptr`".
2. `model_weights_loader.cpp` — `is_relevant_tensor` recognises 16
   new tensor patterns (4 FA proj × {qweight,scales} + 3 DN proj ×
   {qweight,scales}); `dispatch_tensor` routes them via
   `assign_gptq_qweight` / `assign_gptq_scales` to the new fields.
3. `model_runtime.cpp::merge_projection_weights` — every repack/merge
   guarded by `if (fp16_*.weight != nullptr)`; FA k+v merge requires
   BOTH halves FP16; DN qkv merge skipped if `fp16_qkv` is null.
4. `paged_attention.cu::full_attention_forward_paged_prefill` — per-
   projection branch: `gptq_gemm(in, gq, out, M, stream)` when GPTQ
   else `linear_forward(in, fp16, out, M, stream)`. Applies to q/k/v/o.
5. `forward_prefill.cu::deltanet_prefill` — new
   `scatter_dn_qkv_kernel` composes the strided
   `dn_qkv[M, LIN_QKV_AB_DIM]` from the compact GPTQ qkv output and
   the (still FP16) `a`/`b` outputs (A/B are tiny `5120→48` and do
   not appear in GPTQ form in the checkpoint). qkv, z, out each
   branch independently to `gptq_gemm` or `linear_forward`.
6. `forward.cu` — decode path: `full_attention_forward` (M=1) and
   `deltanet_forward` (M=1) branch per projection to `gptq_gemv` vs
   `fp16_gemv`. No scatter needed at M=1 — `gptq_gemv` writes
   directly to the strided offset.
7. `stream.cpp` — kept the env-gated per-step
   `cudaStreamSynchronize` bisect (`DEUSRIDET_DBG_PREFILL_BISECT=1`,
   `DEUSRIDET_DBG_DN_BISECT=1`); zero overhead when unset, useful
   for the next quant-shape mismatch.
8. `configs/machina.conf` — `llm_model_dir` now points at the 27B
   GPTQ-Int4 checkpoint per the user request.

### Task 2 — AWQ A2 probe on cyankiwi Qwen3.6-27B-AWQ-INT4

**Result: A2 (load-time AWQ→symmetric requant) NOT viable; need A1
(true AWQ kernel) or accept dequant→requant quality loss.**

Tensor inventory of cyankiwi/Qwen3.6-27B-AWQ-INT4:
- Format: compressed-tensors **pack-quantized**, group_size **32**,
  asymmetric, `zp_dtype=torch.int8` (stored as int32 packed).
- 64 layers (same as the GPTQ checkpoint), self_attn on layers
  {0,3,7,11,15,19,23,27,31,35,39,43,47,51,55,59,63}, linear_attn on
  the remaining 48.
- Storage axis is `[N, K/8]` (opposite of GPTQ `[K/8, N]`); shape is
  recorded in `*.weight_shape`. `*.weight_packed` is uint32 packed
  along K. `*.weight_scale` is `[N, K/32]` fp16. `*.weight_zero_point`
  is `[N/4, K/32]` int32 (packed int8 zps).

Zero-point distribution (sampled q_proj L3, o_proj L3, in_proj_qkv L0,
out_proj L0, mlp.gate_proj L0, mlp.down_proj L0):
- All six tensors: `pct(zp==8) = 0.000`, `pct(zp==0) = 0.000`.
- min/max span the full int32 range because zps are packed 4-per-int32;
  unpacked int8 zps span the full INT4/INT8 range.
- The "AWQ is approximately zp==8 (symmetric)" assumption is **false**
  for this checkpoint. A trivial A2 cast won't preserve numerical
  quality.

Decision: **A2 is not viable as a free conversion**. To support this
checkpoint we need either:
1. **A1**: a dedicated AWQ-asymmetric matmul kernel (closest
   precedent: Marlin AWQ variant or `auto-awq` GEMM). Largest scope.
2. **A2'**: load-time dequant-then-symmetric-requant with accuracy
   loss measurement (would require sandbox A/B against the GPTQ
   checkpoint on the same prompt set).
3. **Defer**: keep the GPTQ checkpoint as the production 27B path.
   The Qwen3.6-27B-GPTQ-Int4 path is now working at 69 tok/s prefill
   and decode loops cleanly.

No code committed in this work-unit. Probe artifacts and the analysis
are recorded here only.

### Task 3 — Marlin v2 extension over attn/DN GPTQ

**Result: read-only audit complete; implementation deferred pending
Task 1 final accuracy gate.**

`src/machina/marlin_repack.cu::repack_all_marlin` currently iterates
only `mlp.{gate,up,down}_proj` per layer (3 tensors × NUM_LAYERS) and
uses a single device temp buffer sized to the largest MLP qweight
(`HIDDEN_SIZE/8 * INTERMEDIATE_SIZE * sizeof(uint32_t) ≈ 42.5 MB`).
Extending to attn (q,k,v,o) + DN (qkv,z,out) needs:
- iterate `weights.layers[li].full_attn.gq_{q,k,v,o}` for FA-resident
  layers (skip when `qweight==nullptr`), and
  `weights.layers[li].deltanet.gq_{qkv,z,out}` for DN-resident layers;
- temp_buf already covers the largest tensor (q_proj is
  `5120/8 × 12288 ≈ 7.5 MB`, all smaller than MLP);
- `marlin.cu::marlin_gemm` expects the new B layout, so call sites in
  `paged_attention.cu` and `forward_prefill.cu`/`forward.cu` must be
  switched from `gptq_gemm`/`gptq_gemv` to `gptq_gemm_v2`/v2 decode
  variants for the new attn+DN tensors only. The MLP path already
  uses `_v2` per `forward_prefill.cu:41,43,50,53`.

Implementation is mechanical but it is a defaults-affecting prefill
change. Per Constitutional rule, it must ship with a live-system
benchmark on `tests/test.mp3` showing prefill tok/s before/after
without an accuracy regression. Since Task 1 has not produced a
live accuracy number yet (diarizen worker re-loop), the responsible
order is: fix the worker loop OR pivot to a different accuracy
gate first, then ship Marlin-v2 with a properly-paired tok/s line.

No code committed in this work-unit.
