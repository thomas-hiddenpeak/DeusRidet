## Phase 3c — First semantic read of the production diarisation path

Run: `runs/20260526T051055_replay_s600/` — first 600s of `tests/test.mp3`,
replay 4×, reclusterer ON (defaults: W=180s, S=30s, K∈[2,6],
link=0.55, ema=0.20, min_segs=12, max_segs=300, dual-encoder 384D).

Read against `tests/fixtures/test_ground_truth.json` directly by the agent
per the system-level "no scripted scoring on semantic judgement" rule
(`workflow.instructions.md` §Semantic Evaluation, commit 40ab28d).
What follows is *pattern → evidence → suspected cause →
candidate intervention*, no macro-F1.

### Pattern 1 — Catastrophic 4 → 2 global collapse at the first reclusterer pass

**Evidence.** The final forward-map after 600s is `{0,1,2,5} → 1000` and
`{3,4} → 1001`. GT has four speakers (朱杰 / 徐子景 / 唐云峰 / 石一). All
the heavy lifting happens at `t=03:24.500` (the first window-end after
the 180s warmup): in a single burst, raw clusters `0`, `1`, `2` are
all relabelled to global `1000`, while `3` is relabelled to `1001`.
Subsequent passes at `04:10.700` and `05:12.400` only consolidate the
same two buckets.

**Suspected cause.** Within-window K-selection appears healthy — the
eval driver's earlier full-corpus logs show "Optimal K=4 / K=5" being
picked per window. The collapse therefore lives in the **inter-window
Hungarian linker**, not in spectral clustering. The first window
(00:00–03:00) sees raw=0 dominantly producing 朱杰's long monologue
(00:22–00:39, ~10s clean), with raw=1 sprinkled across 朱杰 / 徐子景 /
唐云峰 short turns, and raw=3 just starting to emerge as 唐云峰
(01:42 onward). The Hungarian linker, given a 384D centroid still
dominated by 朱杰's evidence, accepts raw=1 + raw=2 + raw=0 all as
"same global" (link threshold 0.55 is too generous when EMA centroids
have not separated yet) and assigns raw=3 a new global. This matches
the working hypothesis already in `2026-05-26.md` Phase 14 ("full_60m
macro_f1 is dominated by inter-window Hungarian linkage stability").
Production confirms it now.

**Candidate intervention.**
- Tighten linker threshold from 0.55 → ~0.65 *during the bootstrap
  phase* (e.g. first N≤2 windows), or make the threshold a function
  of how many segments the EMA centroid has integrated.
- Require linker bidirectional agreement (candidate must be the
  best match from both sides, not just "above 0.55 to one of the
  globals").
- Bootstrap delay: increase `min_segs` from 12 → ~24 or require
  ≥2 windows before the first relabel event ever fires. Let raw IDs
  accumulate richer evidence before any global merge.

### Pattern 2 — The system self-corrects after ~05:18 once 4 globals exist

**Evidence.** Starting at `06:16.800`, raw `7` appears and stays clean
through `07:05` — every overlap there is 徐子景 (`GT=徐子景  pred=7`).
Starting at `07:20.100`, raw `6` appears and dominates 石一's stretch
through `08:43` (with two stray 唐云峰 utterances mixed in at 08:24
and 08:26, when 石一/唐云峰 alternate rapidly). Crucially, raw=6 and
raw=7 are *not* in the forward-map — the reclusterer never tried to
merge them. So once four reasonably-separated globals exist, the
linker preserves identity. The pathology is bootstrap-specific.

**Implication.** This is encouraging — the steady-state behaviour of
the pipeline is correct. The bug is in the first 3–5 minutes when
EMA centroids are immature. A bootstrap-aware policy (delay first
relabel, tighter threshold while centroids are young) should be a
high-leverage fix.

### Pattern 3 — A long monologue flips global mid-stream

**Evidence.** 唐云峰's 03:27–03:58 monologue is rendered as
`pred=1000` (raw=1) for the first half (03:27–03:43) then as
`pred=1001` (raw=3) for the second half (03:47–03:55). Same speaker,
same continuous utterance, two different global IDs. The online linker
emits both raw=1 and raw=3 within one speech event; the reclusterer
then maps raw=1 to 朱杰's global (1000) and raw=3 to its own global
(1001) — splitting one 唐云峰 monologue across what the listener will
read as two different people.

**Suspected cause.** Upstream raw-cluster fragmentation: the online
speaker-ID + segment-linker stack emits multiple raw IDs for one
continuous speaker turn. The reclusterer is the right place to heal
this, but it heals in the wrong direction because of Pattern 1.

**Candidate intervention.** Fixing Pattern 1 likely fixes this too —
if raw=1 had been linked to raw=3 (both唐云峰) instead of to raw=0
(朱杰), the monologue would be coherent. So the linker policy fix is
load-bearing.

### Pattern 4 — Margin-abstain is well-behaved

**Evidence.** ~25 `pred=-1` decisions, almost all on (a) ≤0.5s onset
fragments, (b) overlap regions where two speakers compete, (c) the
"嗯 / 啊" backchannels that VAD did catch but speaker-ID correctly
refused. None of the `pred=-1` are on confident long-form utterances.
The conservative-abstain pathway is doing its job and is not the
source of error.

**Action.** No change needed here.

### Pattern 5 — VAD drops ~12 short utterances entirely

**Evidence.** "no runtime segment overlaps this utterance" appears
12× in the first 600s, all on utterances ≤2s (e.g. 朱杰 "啊？" at
03:03, 唐云峰 "嗯。" at 08:21, 徐子景 "对." at 09:26). These are
backchannels and one-syllable interjections.

**Suspected cause.** SileroVAD / FSMN-VAD min-speech-ms gate is
likely too long, or the 25-ms hangover is too short to keep
isolated yes/no syllables. This is a `sensus` (perception) issue,
not an `orator` issue.

**Action.** Out of scope for Phase 3. File for later VAD tuning if
the dialogue-understanding stack starts caring about backchannels.

operating on the wrong subsystem.

### Revised root cause — Phase 3c hypothesis was wrong

Phase 3c had hypothesised a "catastrophic 4→2 Hungarian over-merge" at
t=03:24.500 of the production replay. The audit refutes this:

1. **Spectral never picks K=4 in the first window.** Looking at the
   actual 0-180s GT distribution (朱杰 ≈62s monologue + 唐云峰 ≈10s
   short turns + 徐子景 ≈5s + 石一 ≈3s), the data only contains enough
   material for two stable clusters. K=2 is the correct spectral
   answer for the data at that window. The Hungarian linker is
   innocent — there are simply no four clusters to over-merge.

2. **The 3rd and later globals emerge as soon as the window
   accumulates enough material.** Global 1002 is allocated at
   t≈132s, 1003 at t≈303–553s, 1004 in the same range. The
   reclusterer's "discover new speakers as they accumulate" mechanic
   works fine on the fixture.

3. **The discrepancy is between fixture-driven eval and the live
   pipeline.** Eval at s600 → 5 globals, macro_f1=0.9046. Live
   production replay at s600 → only 2 globals (`{0,1,2,5}→1000,
   {3,4}→1001`). Same audio, same reclusterer code, same defaults
   (W=180s, S=30s, thr=0.55, ema=0.20). The bug must live in **what
   the live pipeline feeds the reclusterer**, not in the reclusterer
   itself.

### Phase 3b — revised next steps

1. **Audit live `push()` input.** Add the same env-gated dump on the
   live audio-pipeline side (`audio_pipeline_process_saas_full.cpp`):
   log every `rseg.push()` with seg_id, raw_id, t_start/t_end, and
   embedding L2-norm. Compare segment count and timestamps against
   the fixture for the same audio slice.
2. **Likely suspects** (in priority order):
   - **Gate `match.speaker_id >= 0` drops segments** the eval fixture
     contains. Online linker's "unknown" turns never reach the
     reclusterer.
   - **Live VAD segmentation differs from the offline run that built
     `fused_v1.bin`** — same VAD code path but driven by different
     buffering / replay timing.
   - **Live `dual_emb` extraction**: 384D fused vector is built once
     per finalised utterance from the live FBank stream; the fixture
     was extracted from a different streaming run.
3. **Do NOT tweak link_threshold / min_segs / bootstrap policy yet.**
   The reclusterer is not the broken subsystem. Tightening its knobs
   would mask the real upstream defect.
