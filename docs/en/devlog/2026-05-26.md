# 2026-05-26 — Phase 14: Reliability-Weighted Affinity (Negative on full_60m)

## Summary

Implemented the Phase 13 follow-up that was promised in yesterday's
devlog ("weight the affinity matrix by per-segment reliability
`w_i = min(1, dur_i / 1.5)` *inside* the reclusterer, not as a post-hoc
override"). Code lives where it belongs (inside `build_similarity()`,
gated by config). s1800 lifts cleanly by up to **+1.03 pp**, but
**full_60m regresses by up to −3.56 pp**.

This is the third consecutive lever (Phase 5 K-mode, Phase 8 purity
split, Phase 14 affinity weight) that wins on s1800 and loses on
full_60m. The Phase 6 default `window_sec=180` ceiling
(s1800=0.7935 / full_60m=0.7032) holds.

## Algorithm

In `src/orator/spectral_cluster_affinity.cpp::build_similarity()`,
after the (effectively-disabled) temporal-mixing block:

```cpp
if (affinity_weighted && weights.size() == N && affinity_dur_ref > 0) {
    std::vector<float> w(N);
    for (int i = 0; i < N; ++i) {
        w[i] = std::clamp(weights[i] / affinity_dur_ref, 0.0f, 1.0f);
    }
    for (int i = 0; i < N; ++i) {
        for (int j = i + 1; j < N; ++j) {
            float s = std::sqrt(w[i] * w[j]);
            sim[i * N + j] *= s;
            sim[j * N + i] = sim[i * N + j];
        }
    }
}
```

Diagonal is untouched (self-affinity stays 1.0 — segments are not
silenced, just made less attractive to others). Weights come from
`OratorReclusterer::run_pass()` (segment duration in seconds, same
source as Phase 9).

## Phase 15 — Full GPU port of `spectral_cluster()`

### Mandate

> "我们的计划是要完全通过 GPU 来计算的哟，任何主要计算放在 CPU 上都不是我们
> 的预期设计，CPU 应该只负责任务调度和完全无法在 GPU 上执行的操作。"

Replace the CPU `spectral_cluster` pipeline (Stages 0–9) with a single CUDA
translation unit using cuBLAS SGEMM + custom kernels. CPU is reduced to
task scheduling, host-side K-means++ farthest-point init, eigenvalue
sorting / K selection, temporal-smoothing relabel, and the small
"merge similar clusters" pass — every operation that touches the full
N×dim or N×N tensors is GPU-resident.

### Implementation

- **New**: `src/orator/spectral_cluster_gpu.cu` (~900 lines)
  - Lazy `GpuCtx` singleton owns one cuBLAS handle + one stream + ~25
    grow-only device buffers (`ensure_capacity`). No per-tick `cudaMalloc`.
  - `gemm_row()` row-major SGEMM wrapper. **Subtle bug fixed during
    bring-up**: the standard "swap A/B, swap M/N" column-major trick
    keeps the op flags as identity, not inverted — the first draft
    inverted them and produced `CUBLAS_STATUS_INVALID_VALUE` (error 7).
  - Kernels: `k_col_mean`, `k_subtract_mean`, `k_scale_inv_sqrt`,
    `k_deflate`, `k_l2_normalise_rows`, `k_set_diagonal`,
    `k_temporal_mix`, `k_apply_reliability` (Phase 14),
    `k_clamp_weights`, `k_prune_topp` (repeated argmax + shared-mem mask),
    `k_symmetrize`, `k_row_sum`, `k_orphan_repair`, `k_laplacian`,
    `k_extract_features`, `k_kmeans_finish_dist`, `k_kmeans_assign`,
    `k_kmeans_update`, `k_sum_by_label`.
  - Deflated power iteration (`topk_power_iter`) drives both PCA and
    Laplacian spectral embedding entirely on device.
  - K-means++ farthest-point init runs on host (deterministic seed
    `restart*137 % N`), centroids are pushed to device, then 30
    iterations of assign / update run as device kernels. Length-weighted
    update (Phase 9) is wired.
- **Removed**: `spectral_cluster.cpp`, `spectral_cluster_affinity.cpp`,
  `spectral_cluster_embed.cpp`, `spectral_cluster_postprocess.cpp`,
  `spectral_cluster_stages.h` — five CPU stage files, ~1500 lines total.
- **Unchanged**: `spectral_cluster.h` (public API), `orator_reclusterer.*`,
  `tools/orator_reclusterer_eval.cpp`. Drop-in replacement.

### Numerical verification

| Slice | CPU baseline | GPU port | Δ |
|-------|--------------|----------|---|
| s1800 (`--end-sec 1800`) | 0.7935 | **0.7935** | 0 |
| full_60m (`--end-sec 3600`) | 0.7032 | **0.7032** | 0 |

Bit-identical to four decimals on both slices despite the move to
SGEMM (different accumulation order from the BLAS path). This says
nothing about whether we got "lucky" on these two fixtures, but it
does confirm the algorithm faithfully reproduces every CPU stage.

### Performance (eval CLI, single-thread driver)

- s1800: 16.2 s wall (was ~22 s on CPU build)
- full_60m: 32.7 s wall (was ~50 s on CPU build)

Reclusterer cost is now amortised across many small kernel launches
and a handful of SGEMMs per tick. Headroom exists once we batch ticks
on the stream.
