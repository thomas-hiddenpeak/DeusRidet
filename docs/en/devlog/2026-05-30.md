### What shipped

The native CUDA DiariZen-v2 pipeline (`src/orator/diarizen_pipeline.{h,cpp}`
+ the P3a engine stages: WavLM-pruned, Conformer head, ResNet34 embedder,
VBx clustering) is now wired into the live `awaken` runtime. When
`DEUSRIDET_DIARIZEN_NATIVE=1`, `awaken` loads an in-process
`orator::DiarizenPipeline` at boot and routes the WS `diarizen_finalize`
command through `native->diarize()` on the captured session PCM, broadcasting
the same `speaker_diarize_final` JSON as the worker / facade paths. Gated OFF
by default — zero behavioural change to the shipped Python-IPC pipeline.

`AudioPipeline::diarizen_copy_pcm_f32()` snapshots the int16 capture buffer to
f32 `[-1,1]` (matches the fixture `wave_in` scale used by the P3a bit-eq
dumps).

### Why the default is NOT flipped yet — throughput feasibility

The native `diarize()` is **single-chunk** (no batching): one WavLM-pruned
(24 transformer layers) + Conformer + ResNet34 forward per 1.6 s step, over
~2260 chunks. Measured cost: **0.87 s/chunk → 1943.6 s (RTF 0.54)** for the
60-min session. The shipped Python-IPC path runs the *same* finalize in
753.7 s (RTF 0.21) because the reference DiariZen stack batches at 32.

So the native path is accuracy-parity (slightly better) but **2.6× slower**
than what ships today. Per Prime Directive #9, accuracy decides *improvement*
but throughput gates *feasibility* — flipping the default now would be a
throughput regression. **Batching the WavLM/Conformer/ResNet34 forwards
(batch_size = 32, like the reference) is the gating perf task before the
default-flip.** The single-sequence CUDA forwards (`[C,T]`/`[T,C]` layouts,
no batch axis) make this a large, paced multi-file change; the 60 s-fixture
bit-equality must stay green throughout.

### Memory budget

When `DEUSRIDET_DIARIZEN_NATIVE=1`, WavLM-pruned (120.85 MB) + Conformer
(11.63 MB) + ResNet34 (16 blocks) + PLDA (xdim 256, pdim 128) become
process-resident instead of a Python subprocess. Default-off keeps current
residency (Prime Directive #5).
