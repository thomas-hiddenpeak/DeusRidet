### Diagnosis A — why the online holdback corrected zero times

The first online replay test exposed that the TranscriptHoldback layer
drained every item with its *provisional* online speaker id unchanged —
zero corrections. Root cause, traced through the call graph:

- The only speaker-id rewrite path is holdback's `apply_diarization()`.
- It is called only by `DiarizenPeriodicWorker::run_one_pass_()`.
- That worker runs a pass only when `was_triggered || periodic_enabled_`.
- `periodic_enabled_` was default OFF (needed `DEUSRIDET_DIARIZEN_PERIODIC=1`);
  the awaken log printed `periodic=OFF (trigger/finalize only)`.
- `tools/replay_to_transcript.py` sends only `asr_enable:on` — never
  `diarizen_trigger` / `diarizen_finalize`.

So in the plain replay path no DiariZen pass ever ran, `apply_diarization`
was never called, and the holdback had nothing to apply. This was not a
logic bug — the correction *trigger* simply did not exist in the path the
test exercised.

### Fix B1 + sliding window — proven live

Enabling the periodic worker with a bounded window
(`DEUSRIDET_DIARIZEN_PERIODIC=1`, period 30 s, window 120 s) and reading
the resulting transcript top-to-bottom (eyes-on, no score):

- The worker fired 17 passes; total `changed_pending` = 124 (was 0).
- The cluster→GT picture went from a 5-cluster phantom-fragmented state
  (徐子景 mislabeled as 唐云峰 across her 05:20–05:37 cold-start — the
  long-standing 332 s registration failure) to a **clean 4-cluster
  bijection**: 0=朱杰, 2=唐云峰, 3=徐子景, 4=石一, with 徐子景
  retroactively corrected and 唐云峰's 01:18 cold-start fixed on most lines.
- window=120 s bounded each pass to 8–19 s wall < the 30 s period; live
  ring-buffer overflow stayed at 0 (real-time preserved).

Period = 30 s was chosen from the 17-pass profile: steady-state per-pass
wall was 8.4–19.0 s (max 19.0 s at the densest pass). 30 s gives ~37 %
headroom over the worst pass while keeping holdback/period ≈ 2.5
correction passes per held item; a 75 s+ period drops that to < 1 (the
original bug), and a 20 s period would tie the worst-case wall and back up.

### Anti-entropy — prune the dead config surface, R1-split the header

lines, the entire pre-redesign EMA-library speaker-ID config surface
became 0-consumption (grep: 0 `.cpp` reads, 0 external refs). Removed:

- 22 dead `AudioPipelineConfig` fields plus their `configs/auditus.conf`
  keys and the `awaken.cpp` parser lines + knob-echo printf. The four

  `speaker_margin_abstain`, `speaker_min_fbank_frames`.
- Dead state members `prev_full_*`, `retro_full_ring_`,
  `speaker_run_length_` (0 `.cpp` refs). `prev_seg_*` is **kept** — it is
  the live SAAS_INHERIT path.
- `src/sensus/auditus/retro_full_ring.h` (its only referrer was the
  removed member).

R1 compliance: `audio_pipeline.h` was 795 lines (hard limit 500). Pruning
brought it to 589; extracting `VadSource` + `AudioPipelineConfig` into a
new `audio_pipeline_config.h` (98 lines, now the canonical owner of the
engine-config includes) and tightening two redundant comment blocks
brought it to exactly 500.

### Build repair — vires link debt

The `vires::Arbiter` compute-substrate API is now referenced from inside
two static libraries — `machina` (model_runtime, forward_prefill,
forward_decode register priority streams) and `sensus`
(speech_separator registers a separation consumer). Both linked vires only
transitively through the final `deusridet` target, so every *other*
consumer (`test_forward`, `test_sample`, `auditus_separatio_examen` /
`_asr` / `_spkid`, `test_mossformer2`, `bench_mossformer2`,
`test_overlap_*`) failed at link with undefined references to
`vires::Arbiter::{instance,register_consumer,unregister_consumer,stream,
note_submit}`.

Fix: declare vires a PUBLIC dependency of both `machina` and `sensus`, so
the requirement propagates to every consumer automatically. vires depends
only on communis + cudart, so no dependency cycle is introduced. Full
`make -j` now builds all 43 targets with zero undefined references;
pure-default `awaken` still serves HTTP 200 + WS 101.
